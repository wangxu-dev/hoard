# Hoard website

Next.js static website in the Hoard repository. Bun workspaces use the root lockfile. The desktop frontend remains in `web/`.

Run `bun run dev:site` at the repository root and open http://127.0.0.1:3000. This first builds the embedded APP demo, then starts Next.js. When changing `website/demo/` or APP components during a preview session, run `bun run --cwd website build:demo` to refresh the embedded bundle.

Validation: `bun run test:site`, `bun run typecheck:site`, `bun run build:site`. After `bun run generate`, run `bun run typecheck:demo` to typecheck the demo together with the original APP components and generated API types.

## Cloudflare Workers deployment

Connect the GitHub repository in Workers Builds. Use production branch `main`, repository root `/`, build command `bun install --frozen-lockfile && bun run build:site`, deployment command `bunx wrangler deploy`, and preview command `bunx wrangler versions upload`. Preview builds can stay disabled. Set build variables `BUN_VERSION=1.3.11` and `NODE_VERSION=22`.

The root `wrangler.jsonc` defines `hoard-website`, the static asset directory `website/out`, 404 routing and a fixed compatibility date. That date selects Cloudflare runtime behavior and does not change with APP releases or deployment dates. No Worker server script is required. `bun run --cwd website deploy:check` validates the deployment locally without account access; CI runs it after the website build.

Set `NEXT_PUBLIC_SITE_URL` to the final HTTPS origin without a path before the production build. Until then, preview builds disable indexing. Website HTML is already statically prerendered, including its SEO metadata; SSR is not required for the current content.

## Static deployment

Set `NEXT_PUBLIC_SITE_URL` to the final HTTPS origin without a path and run `bun run build:site`. Deploy `website/out/` to a static host. No Next.js server is required. Without this variable, preview builds disable indexing and omit canonical URLs. The build environment owns this setting; local environment files are not committed.

Chinese is at `/`, English at `/en/`, with a privacy page for each language. Metadata, alternate language URLs, robots and sitemap use the configured origin. Version and download filenames follow `mygo.json` and the existing GitHub Release naming convention. Rebuild after publishing a release.

## APP reuse

`website/demo/` is a Vite entry that imports the original APP's AppSidebar, LibraryPage, LibraryGrid and TimelineScrubber. Its `@mygo` alias supplies a local mock backend. Desktop generated bindings and runtime are absent from the deployed demo. Sidebar, toolbar, card layout and interactions come from the APP; the exported EntryCard is also used by the hero illustration. Demo account names, avatars, titles and dates are fictitious. Work clicks and backend actions are disabled silently.

The demo sits inside a macOS-style shell occupying 85% of the viewport width. The contents render at 85% scale; the shell height fits below the sticky navigation. Red/yellow/green controls are decorative. All native scrollbars stay hidden. Anchor navigation provides direct access to preview, downloads and FAQ.

Website controls directly reuse APP components through `@app-ui`. Tokens come from `web/src/styles/theme.css`. Accordion, BlurFade, AnimatedBeam and Marquee are generated by the registry CLI. App-specific styles and components are not duplicated. The platform strip distinguishes current support through color; other platform icons represent future exploration, not delivered integrations.

Simple Icons are CC0; Lucide is ISC; see `../web/LICENSES.md`. Temporary scripts, browser screenshots and reports stay in ignored `.agent/`.
